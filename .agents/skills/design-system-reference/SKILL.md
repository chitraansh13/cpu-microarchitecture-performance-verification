# Design System Reference

When designing or refining the frontend:

1. Read `references/DESIGN.md` before making visual decisions.

2. Treat the reference as design guidance, not as an instruction to clone another company's product.

3. Adapt its:
   - spacing
   - typography
   - hierarchy
   - component density
   - layout principles
   - interaction patterns
   - visual restraint

   to this project's own identity:

   CPU Microarchitecture Performance Verification

4. Preserve the engineering-console character of the product.

5. Do not copy:
   - logos
   - trademarks
   - company names
   - proprietary product copy
   - brand-specific illustrations

6. Do not turn the project into a generic SaaS dashboard.

7. Prefer:
   - neutral/slate/graphite surfaces
   - strong information hierarchy
   - compact technical data presentation
   - monospace where useful for traces/addresses/results
   - modern sans-serif for normal UI text
   - semantic PASS/FAIL/warning colors
   - restrained interaction motion

8. Combine this skill with:
   - `design-taste-frontend` during creation/refinement
   - `web-design-guidelines` during review/audit
